# KDL の保存差分の試作

対象は [KDL の編集試作で保存差分の保証を検証する](https://github.com/daaa1k/psycho/issues/12)。
`demo.html` をブラウザーで開くと、入力と出力、操作、診断を確認できる。
製品実装ではなく、有限個の操作を検証して記録した使い捨ての試作である。
2026-09-28 にユーザーが方式の採用を決定した。
決定の正本は [解決コメント](https://github.com/daaa1k/psycho/issues/12#issuecomment-5870018414) を参照する。
以下は採用判断に提示した時点の検証記録である。

[対応表](../../referent-table-kdl-edit-prototype.md) を先に保存した。
SHA256: `008ad495209ad611aa214b02ab92a4f2cf7db03c0089d67a631b0e30438c45f6`。

## 実行結果

2026-09-28 に macOS、Rust 1.98.1 で実行し、10 例、26 操作が期待どおりになった。
26 操作には、重複属性の診断実験 1 件と、内容が変わる移動を確定しない実験 1 件を含む。
全件が有効な編集という意味ではない。
ブラウザー用の JavaScript でも 26 操作の UTF-8 差し替えを再実行し、Rust の出力との一致を確認した。
DOM を模した実行でも各状態の描画と保存ボタンの処理を確認したが、実ブラウザーでの画面確認は未実施。

| 確認対象 | 観測 |
| --- | --- |
| 無編集保存 | BOM、CRLF、末尾改行なし、子ブロックの後の空白を完全保持 |
| 値だけの変更 | 本文、画像パス、属性の値の範囲だけを差し替え、範囲外のバイトが一致 |
| コメントと移動 | 独立コメントは元の場所に残り、内部と同じ行の末尾コメントは要素に追従 |
| セミコロンと削除 | セミコロン後のコメントを画像に伴わせて削除。同じ行の二つ目の要素も移動 |
| 列の内外への移動 | 通常文字列、生文字列、複数行文字列、生の複数行文字列の値と構造が一致 |
| 要素の追加 | 先頭、末尾、空の Slide への追加。タブと CRLF に合わせ、既存行を保持 |
| 連続編集 | 操作ごとに再解析し、長さが変わった後でも重複属性の両方の位置が原文と一致 |
| インデント変更の反例 | 有効な構文と Schema のまま文字列内容が変わる例を検出 |
| 文字列表記の保持 | 反例の文字列をそのまま保持すると、列への往復移動で内容が一致 |
| 字句の区別 | 入れ子コメント、slashdash、タブ、CRLF を含む例で引用された表記が完全一致 |

入力、出力、差し替え範囲、再解析した構造、診断は `results.json` に記録した。
`demo.html` は同じ記録を内包しており、ネットワーク接続なしで動作する。
任意の KDL を入力して解析するアプリではない。
自由操作は、記録された各操作の直前へ戻って再生する形で提供している。

## 判明した補完処理

原文の保持とバイト範囲の差し替えで、今回の未編集部分の保証を満たせた。
`kdl` 6.7.1 は変更後の解析と位置取得に使い、文書全体の再出力は保存に使わない。
値の範囲は entry の終端と保持された `value_repr` の長さから求め、原文との一致を確認した。
毎回解析し直すことで、古い位置を次の編集に使うことを避けた。

コメントの所属には原文上の位置を使う追加処理が必要だった。
特にセミコロン後の末尾コメントは、ライブラリが格納するノードとは別に所属を判定した。
移動と削除の範囲に独立コメントを含めず、移動先の行頭と終端を補った。

複数行文字列では、行頭空白の一律変更だけでは保存仕様を満たせない。
閉じ引用符が行頭にある例で、本文の空白だけが増え、解析後の文字列内容が変わった。
この例は構文と Schema の両方で有効だったため、変更前後の値の比較が必要だった。
試作ではその差を検出した候補を確定せず、原文を保持する状態も記録した。

同じ反例について、引用された文字列全体をバイト単位で保持し、その外側だけをインデント変更する処理を試した。
通常の引用と生文字列、複数行文字列、コメントを小さな走査処理で区別し、列への往復移動後も値が一致した。
この方法では本文と閉じ引用符が元の桁に残る。
保存仕様は文字列内容の保持を求めており、移動時のインデント変更は許容しているため、この差分を採用候補とする。

## 採用判断の提案と限界

原文への差し替え、`kdl` による再解析、原文上の位置によるコメント所属、移動時の文字列表記の保持を組み合わせる方式を推奨する。
一律のインデント変更を一般解として採用することは推奨しない。
試作には両方式の差が残っており、採用候補は文字列表記を保持する方である。
ユーザーには、文字列の本文と閉じ引用符が元の桁に残る具体的な出力を確認してもらう。

今回の実行は列挙した入力に対する実現可能性の証拠であり、KDL 2.0 全体への適合証明ではない。
型注釈、Unicode の改行と空白、あらゆる行継続、すべてのコメント配置、混在改行での書式推定は網羅していない。
原文の走査処理と Schema 検証はこの実験用であり、そのまま製品コードとして採用しない。
挿入位置も実験に必要な先頭と末尾に限定した。
Schema の全制約への適合試験、ファイルへの原子的な書き込み、外部変更との競合、Undo / Redo、性能は未検証。

## 再現方法

Rust 1.95 以上で、リポジトリのルートから次を実行する。
依存は `Cargo.lock` と `kdl-rs` の commit `8dac0428c75e09d22078b3a1703c70bb0912392d` に固定している。

```sh
cargo run --locked --manifest-path prototypes/kdl-preserving-edits/Cargo.toml
```

Cargo がない Nix 環境では次を使える。
Nix のツールチェーン自体はこの試作では固定していない。

```sh
nix shell nixpkgs#cargo nixpkgs#rustc -c cargo run --locked --manifest-path prototypes/kdl-preserving-edits/Cargo.toml
```

`results.json` と `demo.html` を再生成する。
`viewer.html` は結果を埋め込む前のテンプレートである。
