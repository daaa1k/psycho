# Issue #30の証跡

最終製品ソースは`8dc2ce3`。ケースと採用した実行の対応は[受け入れ記録](../../issue-30.md)に記載する。原manifestは実行結果を変更せずに保存する。

- `final/`は初回実行。16ケースがPASSで、Columnsの観測取得失敗により全体はFAIL。
- `final-tail/`は5ケースがPASSで、閉じるボタンのOCR認識失敗により全体はFAIL。
- `final-rest/`は6ケースがPASSで、保存失敗検証の古い入力座標により全体はFAIL。
- `final-last/`は入力欄のOCR差異を記録した未合格実行。
- `final-complete/`は残り2ケースを共有GUI検証器から最初から実行した記録。
- `final-diagnostics/`、`final-diagnostics-2/`、`final-diagnostics-3/`は診断文字・選択記号のOCR誤読を保存した未合格実行。
- `final-diagnostics-4/`は構文・Schemaの読み取り専用行と画像診断の移動を確認した合格実行。
- `history/`は原文・nativeの失敗する再現と修正後の記録。
- `fonts/`は実際のPostScript名と、計測用依存ソースを復元したビルド記録。
- `supplemental-retina/`は必須の単一画面環境に含めない、未合格の補助測定。

PNGとCSVは画素・配置の検査、MOVは操作経過の確認に使う。生成バイナリーは含めない。KDLは検査時に比較した保存バイトの証跡であり、画像参照の一部は検査用`target/`の相対位置を指す。別の環境へコピーして開くfixtureとしては扱わず、再実行器で専用コピーを生成する。

履歴上限ケースでは検査に使わない全描画の重複トレースCSVが生成される。このファイルだけは`target/`に保持し、リポジトリーには[サイズ・SHA-256・除外理由](archive-omissions.json)を記録する。履歴の実際の合否はnative入力状態、保存原文、ログで確認する。配置比較に使った座標CSVはすべて含める。

保存原文と実行ログは採取したバイトを保持する。KDLの末尾空白・CRLFとログの末尾空行も検査対象や出力の一部なので、整形しない。コードと文書の空白検査は生のKDL・log証跡を除いて行う。
