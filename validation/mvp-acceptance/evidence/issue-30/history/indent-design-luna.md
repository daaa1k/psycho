# 移動ソースのインデント設計案

## 現状と失敗形

移動系の複数メソッドは `node_line_range` でソース片を切り出し、`reindent_moved_source` を通して `insert_moved_source_at` に渡す。現行の再インデントは `collect_node_offsets` が返すASTノード名の位置だけを置換するため、ノードではない行が元の列に残る。複数行文字列の内容行、コメント、閉じ括弧がその例で、`prototype_10_01` は文字列内部の空白を変えずに移動する必要を示す。`prototype_02_01` は内部コメントと末尾コメントをノードに伴わせ、移動先で揃える契約を示す。

`prototype_02_03` は同じ物理行にある兄弟ノードの後半を動かすケースである。ここではノード開始位置からの断片が行頭インデントを持たないため、「断片の各行頭に宛先インデントを付ける」だけでは、元行に残った兄弟やセミコロンとの境界が壊れる。切り出し境界でインラインノードを独立した行へ分離し、同じ行に残る兄弟の側も空白だけを残さない扱いが必要。

`prototype_07_02` は空の親に子を追加するとき、既存文書のタブとCRLFを維持するケースである。インデント幅や単位を空白4つに固定してはならない。指定ログ `logtarget/issue30/regression-strengthened.log` はこの作業ツリーには存在せず、テスト定義を根拠にした。

## 案: 字句保護付きの物理行変換

ノード位置だけを変換対象にするのでなく、切り出したソース片の全物理行を基準インデントから宛先インデントへ写像する。KDLの引用文字列を字句スキャンして得た保護範囲を使い、引用範囲内のバイトは一切置換しない。複数行文字列の内容行と引用表記も含め、保護範囲はバイト単位で不変にする。

```rust
struct SourceScan<'a> {
    source: &'a str,
    quoted_ranges: Vec<Range<usize>>,
    // コメント範囲と物理行境界は同じスキャン結果から導出できる。
}

fn scan_source(source: &str) -> Result<SourceScan<'_>, DocumentError>;

fn reindent_moved_source(
    moving: &str,
    source_indent: &str,
    destination_indent: &str,
    indent_unit: &str,
) -> Result<String, DocumentError>;
```

`scan_source` は既存の `normalize_line_endings_outside_strings`、`skip_quoted`、コメント走査が持つ字句規則を一つの内部スキャナへ寄せる意図の名前である。現行ソースに `scan_source` という関数名はなく、文字列・コメントの走査処理が複数箇所に分かれている。移動専用の簡易文字列検出器を追加せず、その規則を共有する。

変換は次の順に行う。

1. 断片の字句スキャンで引用文字列範囲を得る。
2. 物理行ごとに、引用範囲外にある行頭の空白・タブだけを変換候補にする。行頭が複数行引用文字列の内部ならその行は無変更とする。引用範囲と交差する行頭は、範囲外の連続する接頭空白だけを変換し、範囲内のバイトは触れない。
3. 元のルートノードの基準インデントから各行の相対インデントを求め、宛先の子インデントと相対差から新しい接頭辞を作る。コメント行と閉じ括弧も通常の物理行として同じ規則を使う。
4. CRLF/LFの正規化は従来どおり引用文字列の外だけで行う。タブ文書ではタブを単位として保持し、混在または判定不能な場合は宛先兄弟の既存字下げ差を優先する。

相対深さはノードASTから再構成せず、行頭の字下げ差を保持する。これにより、内部コメント、閉じ括弧、ノードではない構文行も同じ移動方針を受ける。兄弟ノードがインラインで並ぶ場合は物理行変換に入る前に、対象ノードの構文境界を使って対象だけを独立行にする。元の行に残る前後の構文も有効な行頭・セパレータに整える。行変換器自体にはノードASTの再帰構造を持たせない。

挿入先のインデント推定は `child_insertion` と `reindent_moved_source` の別実装にしない。親の実インデント、既存子の実インデント差、近傍の字下げ文字種から `(child_indent, indent_unit)` を返す単一の内部ヘルパーを使い、追加と移動の両方から呼ぶ。子がない場合は近傍の兄弟差を使い、差がなければ文書内の優勢な字下げ文字（タブまたはスペース）を使う。幅をバイト長だけで比較せず、字下げ単位の列として扱う。

## ノードオフセット方式との比較

現行のASTノードオフセット方式はノード名だけを正確に直せる一方、コメント・括弧・任意の字句行に同じ構造情報を別途追加し続けることになる。字句保護付き行変換方式は、インデントという物理行の性質を一か所で扱い、文字列の保護も同じスキャン結果で保証できる。ASTは切り出し対象とインライン兄弟の境界特定に残し、行の相対字下げを決める用途から外す。

注意点は、引用範囲内にある行の先頭空白は内容そのものなので移動先に合わせられないこと、またインライン兄弟を分割する境界処理が必要なこと。これは仕様上の保護要件とKDL構文上の現実であり、通常行と同じように変更してはならない。失敗時は部分変換で続けず `UnsafeValue` を返す。

## red flags 確認

- **情報漏洩 / 二重のやり方:** 移動と追加が別々に字下げ推定を実装しない。字句規則も既存の文字列・コメント走査と共通化する。
- **浅いモジュール / pass-through:** 公開APIは変えない。内部ヘルパーは推定と変換の複合責務を持つ操作境界に留め、段階ごとの薄い転送関数を増やさない。
- **分割所有:** インデント方針を一つの推定ヘルパーに置く。呼び出し側がタブ幅や相対深さを再計算しない。
- **時間分割:** 解析・再インデント・挿入で同じ不変条件を独立管理しない。変換済み断片が引用内容不変と行境界条件を満たす責任を変換関数に置く。

既存APIのシグネチャと外部動作は維持できる。実装上の中心は、複数箇所に散らばった字句走査規則を共有可能なスキャナへ統合し、挿入・移動の両方が同じ宛先インデント推定を使うこと。
