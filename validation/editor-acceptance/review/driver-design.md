# 独立比較

推奨ベースは sol。既存の `Gui` 公開 API を維持し、二操作だけの Swift helper に AX と入力配送をまとめる。astra から「対象欄を含む AXWindow から座標を取る」「配送が曖昧なら再送しない」を明文化する。luna の既存 helper 再利用は最小差分だが、現行試作の座標対応と対象焦点の弱さを残す。

| 候補 | 所有 PID・window・field・焦点 | 最小 API・保守性 | IME・実 chord | 配送と結果・再送・待機 | 合計 |
| --- | ---: | ---: | ---: | ---: | ---: |
| astra | 3 | 2 | 3 | 3 | 11/12 |
| luna | 1 | 3 | 3 | 2 | 9/12 |
| sol | 3 | 3 | 3 | 2 | 11/12 |

点数は設計の契約を評価する。実装成功の証拠ではない。sol の最終項目は自動再送禁止が明示されていないため減点した。astra は操作ごとの詳細 JSON 記録まで必須化し、今回必要な診断より公開境界が重い。luna は意図する API が小さい一方、focused の確認が選んだ欄を特定せず、既存 helper が常に対象 PID にクリックを送るという説明も実装と異なる。

## 読んだ実装とログの根拠

- 現行 `focus_input` は正確なラベルで一つの AXTextField を選ぶが、別途最初の AXWindow を選び、その原点を引く。`native_double_click.swift` は最初の layer 0 CGWindow の原点を足す。単一画面・単一文書なら一致する可能性は高いが、その対応を検査していない。helper のクリックは `post(tap: .cghidEventTap)` であり PID 宛てではない。前面 PID とウィンドウ内座標の検査はある。
- `focus_input` の成功判定は CSV の `focused` だけで、別の入力欄の焦点でも成立する。文字の置換後の CSV 値一致も、入力先を単独では証明しない。対象欄の AX 焦点か、それに代わる実機で確認した対象固有の観測が必要。
- 現行 Escape は既存 `overview/keys.swift` の `postToPid` を使う。送信後の `.25` 秒待機は製品成功を証明しない。結果はレシピが検査する契約にする。
- sample/blank のログは `No focused scratch text input`、document-status/document-present は旧 `Gui.key` の `window_not_focused`。現行試作の成功・失敗はこの四ログから判定できない。sample の旧操作は OCR 座標クリックであり、候補中の「AX 要素クリックだった」という断定も根拠にしない。

## 採用する最小の補強

1. 生存中の `Popen` の PID と前面 PID を検査する。既知の実行パスとの一致は小さい境界検査として採用できるが、パスだけを別の所有権モデルに育てない。
2. 正確なラベル・role・可視性で欄を一意に選び、その欄のグローバル座標を使う。単一文書という前提は一意性の検査で明示する。複数候補時は停止し、一般的なウィンドウ探索・対応アルゴリズムは作らない。
3. 対象欄の焦点と CSV の編集焦点を期限内に観測する。GPUI が AX 焦点を提供するかは未確認。提供しない場合に新しい AX エンジンを作らず、対象欄の値と保存結果など、既存レシピで成立する代替証拠を記録して契約を調整する。
4. Escape は一回の実キー配送に限定し、モーダル消失、draft 維持、全画面復帰を各レシピの期限付き観測で判定する。配送後の曖昧なエラーを再送で隠さない。診断は PID・ラベル・直近の観測・失敗理由があればよく、全操作共通の JSON 記録方式は必須にしない。
5. #77 の `hotkey('CmdOrCtrl+S')` を実 chord のまま残す。全候補に共通して、既存 `act` の hotkey 向け restore 再試行は残る。今回それを全面改修する必要はないが、その再試行が発生した #77 実行を無条件で受入証拠にしない。実際の送出回数と marked text、draft、保存結果を確認する。

複数ディスプレイ対応、複数文書の自動選択、backend 切替、汎用キー配送、menu 保存への置換、永続的な AXIdentity 管理は今回の範囲を広げる。新規 helper は二操作で止める。最終判定は新しい scratch 出力で四ワークフローを実行し、対象入力欄への編集と既存の保存・復帰条件が成立すること。UI・ビルド・コード変更はこの評価では行っていない。
