# 独立レビューの判断

gpt-6-astra、gpt-6-sol、gpt-6-luna が同じ Issue #51 の意図とコード品質基準で差分を読みました。修正後の製品コードに確定した blocker はありません。

| 指摘 | 判断 | 結果 |
| --- | --- | --- |
| 右クリックメニューの読み上げ名が「表示」になる | 修正 | 「スライド」へ変更 |
| 右クリック操作後に Navigator のフォーカスが戻らない | 修正 | 呼出元のフォーカスを戻して共通操作を実行 |
| 通常の Escape がメニュー取消へ届かない | 実機で再現して修正 | ドラッグ状態がない場合は既存処理へ伝播 |
| 一覧見出しへのドロップでドラッグ状態が残る可能性 | 判定範囲を整理 | 取消とドロップが同じ一覧の hitbox を使う。旧版の実機では状態残存を再現せず、確定不具合とは扱わない |
| 描画時に原文を Arc へコピーする | 非 blocker | 今回は独立キャッシュを追加しない。100 枚の実操作は通ったが、コピー費用の性能測定は実施していない |
| GUI の受入検証が差分にない | 修正 | スクリプト、観測、画面、KDL、テストログを追加 |
| 無効入力と外部競合の証跡が旧リビジョン | 修正 | 最終製品コードで再実行してリビジョンを照合 |

最新 main へのリベースは競合なく完了しました。`git range-diff 5ee83e6..2b6c8e5 17133d5..7675694` で 5 コミットすべてが `=` となりました。gpt-6-astra はリベース後の入力確定と外部変更処理との接続も再レビューし、確定 blocker はありませんでした。リベース後の実ウィンドウ結果と全テストは、このディレクトリの証跡です。

文書編集、履歴、Navigator の状態が同じ契約を持つため、実装は独立 worktree の 1 owner に集約しました。設計比較、独立レビュー、GUI ドライバーを分け、GUI 操作は直列で実行しました。選択状態を別 Session へ移す案は採用せず、既存の文書操作と共有アクションを再利用しました。
