# Issue #53 独立レビュー（ed055bd）

## 対象と判定

`c64a70f..ed055bd` の `src/main.rs` と `src/input.rs`、Issue #53・#48・#67 を確認した。目的は、選択に応じた Inspector、全 Element に届くスクロール可能な構造一覧、種別別設定、コード言語、共有入力と履歴、IME・外部競合、キーボードと VoiceOver、および診断フッターの高さ制限である。実画面の長い構造、列内、画面外、言語プリセット、保存と履歴は実装担当の証跡で通過済みとの連絡を受けた。私は固定ソースの静的レビューを行い、実装担当の GUI プロセスとテスト環境には触れていない。

## 修正対象

1. **[warning、新規] 構造一覧の全行が Tab 停止点になり、設定欄へ到達しにくい。** `src/main.rs:2994-3053` の `render_element_outline` は全行を描画し、`render_outline_row` は各行へ `styled_button(..., true)` を使う。`styled_button` は `src/main.rs:6291` 付近で `tab_stop(enabled)` を設定する。したがって100行の Slide で一覧先頭の行に Tab で入り、設定へ進もうとすると、残りの全行を Tab で通過する。リストの `aria_description` は「上下キーで項目を選択、Tabで設定へ移動」と案内するが、実際の Tab 動線と違う。Issue #53 のキーボード到達性に直接反する。リストの Tab 停止点を一つに絞り、フォーカス中の行だけを矢印キーで移動する方式にする。修正後は先頭、中間、末尾の選択状態から Tab 一回で設定の最初の操作へ移れることを実画面で確認する。

2. **[critical、既存の潜在不具合で受け入れ操作により顕在化] 無効な列幅入力を Inspector を閉じて隠せる。** `src/main.rs:340-355` の `toggle_pane` は Inspector を閉じる前の `commit_draft` を `!self.canvas_editing` のときだけ行う。`select_columns` と `select_column_width`（同 `:764-830`）は `canvas_editing` を消さない。キャンバス上の直接編集から 2 列を選び、幅の数値入力へ移った状態で `0` を入れると、フラグが真のままなのでペインを閉じる操作は妥当性検査を通らない。無効値を持つ入力欄が消え、Issue #53 の「無効入力なら切り替えない」契約に反する。`canvas_editing` を編集面の切替時に正しく更新し、閉じる操作もフォーカス中のドラフトを実際の入力状態で判定する。これは `c64a70f` にもあった経路で、`ed055bd` が導入した問題ではない。実装担当が実画面で再現し、後続コミットで修正中と連絡済み。

## 検討事項と証跡

- `render_element_outline` は `ScrollHandle::scroll_to_item` を選択変更時に呼び、画面外選択を見せる。GPUI の `ScrollHandle` は直接の子要素の境界を使うため、ここで各行を直接の子にした実装とは整合する。スクロール実装に静的な欠陥は見つけていない。
- `apply_code_language` は現在のドラフトを確定してから同じ Element の言語フィールドへ移り、プリセット値を文書へ確定する。手入力の未対応言語は選択し直すまで保持される。ここにも追跡可能な欠陥は見つけていない。
- VoiceOver がリストの選択状態、各入力の制約、無効状態をどう読むかはコードだけで合否を確定できない。`Role::ListBoxOption` と `aria_selected`、入力の `aria_label` は設置されている。Tab 停止点の修正後、標準日本語 IME を含め、Issue #53 に指定された実機操作の証跡を確認する必要がある。
- `src/main.rs` は変更前から数千行で、この差分による 1000 行閾値の跨ぎではない。長さだけを理由に本差分のブロッカーとはしない。

## 却下した疑義

- `scroll_to_item` を普通の `div` に使えないという疑義は誤り。使用中の GPUI に `ScrollHandle::scroll_to_item` があり、`overflow_y_scroll().track_scroll(...)` の子境界を使う。
- 言語プリセットが未対応言語を自動変換するという疑義は誤り。プリセットのクリック時にだけ変換され、自由入力の導線が残る。
